# Правила разработки Restart B2B

Обязательные правила для всей разработки. Не забывать.

---

## Дизайн

- **Дизайны брать с MCP:** референсы и структуру страниц смотреть через MCP (браузер, fetch) — не придумывать «в воздухе». При необходимости открывать эталонные сайты и брать оттуда идеи.
- Стиль: **XXI век** — современный визуал (2020-е), корпоративный 2026: чистая сетка, типографика, минимум декора, акцент на контенте.

---

## MCP

- **Использовать все MCP** где уместно: браузер (cursor-ide-browser / cursor-browser-extension) для дизайна, вёрстки и тестов; fetch — для контента с сайтов.
- Дизайн и референсы — через MCP. Перед релизом или сдачей этапа — проверка в реальном браузере через MCP.

---

## Чистота репозитория

- **Не создавать:** отчёты, тестовые файлы, временные файлы, мусор (например `test-*.js`, `temp-*.json`, `report-*.md`, `*.bak`).
- Если временный или тестовый файл создан — **сразу удалить** после использования. Не забывать чистить.
- В репозитории только рабочий код и необходимая документация (карта, TODO, спецификации, бренд).

---

## Поэтапность

- Делать **сразу правильно**, **поэтапно**: по фазам из RESTART-DEV-MAP.md и TODO.md, без хаотичных правок.
- Один этап — законченный кусок (страница, фича, API), без полуготовых «заглушек» в прод.

---

## Краткий чек перед коммитом

- [ ] Нет лишних/тестовых/временных файлов?
- [ ] Дизайн в духе XXI века?
- [ ] При необходимости — проверка в браузере (MCP)?
